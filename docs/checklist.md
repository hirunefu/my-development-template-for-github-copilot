# 導入後の確認

**読み手**: 導入作業を終えた人。

まずこれを実行する。

```
python3 scripts/verify.py
```

以前ここに並べていた目視確認は、すべてこのスクリプトに移した。テンプレートの説明の残り、用語集、ADR、`.gitignore`、帰属表示、参加者ガイドの空欄、相対リンク、指示ファイルの整合を見る。GitHub を使っていて `gh` が認証済みなら、workflow の実行・ラベル・ブランチ保護・required check の名前一致も見る。

失敗した項目には直し方が出る。**終了コード 0 になるまで繰り返すこと。**

## 機械では確認できないもの

`verify.py` が通っても、次の 2 つは残る。

### 1. CI が実際に緑になるか

required status check にする**前に**、変更提案を 1 つ作って CI を走らせ、緑になることを確認する。

既存プロジェクトに導入した場合はとくに重要で、既存のバイナリ資産が原因で `skillspector` が落ちることがある。対処は `README.md` の「analyzer の劣化で落ちたとき」を参照。

**順序を誤ると、報告されない check を待って変更提案が永久にマージできなくなる。**

### 2. 参加者ガイドの中身が正しいか

`verify.py` は `docs/onboarding.md` の空欄が**埋まっているか**は見るが、**書いてある内容が正しいか**は見ない。

書いたら、**そのプロジェクトを知らない人に読ませて、実際に環境を立ち上げてもらうこと。** 立ち上がらなければ、そのガイドはまだ完成していない。

## skill を導入した場合

```
copilot skill list
```

`setup-matt-pocock-skills` を含む一覧が出ること。Claude Code なら `/` を入力して候補に出るか確認する。導入手順は `docs/skills.md`。

自分で書いた skill を `.claude/skills/` に置いた場合は、同じ一覧に Project skills として並ぶ。書き方は `docs/skills-authoring.md`。
