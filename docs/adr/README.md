# Architecture Decision Records

**読み手**: このプロジェクトの設計決定を記録する人。

このプロジェクトの設計決定を記録する場所。`0001-<slug>.md` から連番で置く。

まだ 1 本も無いのが正常な状態。**先回りして書かない。** 実際に決定が起きた時点で追記する。

記録する価値があるのは、次の 3 つをすべて満たす決定だけ。

1. **取り消しが難しい** — 後から変える費用が大きい
2. **文脈がないと驚く** — 後から読む人が「なぜこうなっているのか」と考える
3. **実在のトレードオフの結果** — 選ばなかった選択肢があり、理由があって今の形になった

1 つでも欠けるなら書かなくてよい。取り消しやすい決定は変えればいいし、驚かれない決定は誰も理由を探さないし、選択肢が無かった決定に記録すべき理由は無い。

書式は 1 段落でよい。表題と、文脈・決定・理由が伝わればそれで足りる。

なお `docs/template/adr/` が存在する場合、それは**このリポジトリの土台になったテンプレート自体**の設計記録で、このプロジェクトの決定ではない。混同しないこと。複写先では削除されていることがある。
