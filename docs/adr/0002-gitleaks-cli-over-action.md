# gitleaks を公式 Action ではなく CLI 直実行で動かす

CI では `gitleaks/gitleaks-action` を使わず、リリースのバイナリを取得して直接実行する。

## 背景

`gitleaks-action` は **Organization が所有するリポジトリではライセンスキーが必須**で、`gitleaks.io` でキーを取得し `GITLEAKS_LICENSE` を secret に登録する必要がある。個人アカウントのリポジトリでは不要。

このリポジトリはテンプレートであり、複写した利用者が Organization に所属している可能性がある。「複写してすぐ動く、セットアップ手順ゼロ」を制約に置いた以上、利用者にキー取得と secret 登録を強いる構成は採れない。

gitleaks の **CLI 本体は org でも無料**で、この制約はもっぱら Action 側に由来する。

## 決定

リリースアーカイブを `curl` で取得し、同じリリースの `checksums.txt` で SHA-256 を検証してから実行する。バージョンは workflow 内の `GITLEAKS_VERSION` に固定する。

チェックサム検証を省かない理由は単純で、秘密の混入を検査する CI が、その検査ツール自体を無検証で取ってくるのは筋が通らないため。

## 却下した選択肢

- **`gitleaks-action@v3`** — 公式で PR コメントなどの機能が付くが、上記のライセンス要件がテンプレートの前提と衝突する。
- **Docker イメージ (`zricethezav/gitleaks`)** — ライセンス縛りは無いが、バイナリ直実行より遅く、バージョン固定がタグ依存になる。

## 帰結

- 呼び出し方は自分で書く。`--redact` は必須で、外すと検出した秘密そのものが CI ログに出力される。
- バージョン更新は手動。`uvx` や `curl` によるピン留めは Dependabot の追跡対象外で、放置すると黙って古くなる。更新手順は `README.md` に記載してある。
